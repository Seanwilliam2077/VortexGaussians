# One-step certificate for the sampled heating operator

The input consists of the present state of an edited shot and the registered list of material sites to monitor. The implementation targets the pinned layered VPM step at 1/60 s, unit scene scale, zero yaw/pitch, the world slice convention, no base emitter, and all layers simulated. Native positions and transforms here are finite and well inside the 1e−9 rounding allowance. The returned yes identifies a site that crosses the native inclusive ignition threshold on the next scan. No certifies that none of the currently unlit, fuel-positive sites in the supplied region crosses on that scan.

1. **Particle membership.** VPM physically writes its output list in stable Morton order of the current particle positions. Visual temperature and density after this update are determined from their present values; dynamic temperature affects the field but does not replace visual temperature in the ignition kernel. The native velocity norm is capped at four before storing each component in binary32. Over one step, displacement is within a horizontal disk of radius 4.000002 times dt plus a geometric allowance. Layer depth is fixed. An object outside the post-cooling temperature or density constraints retires. The remaining uncertain cases straddle x or y clipping boundaries. No newly emitted scene carrier can enter this scan because scene feedback follows the material scan.
2. **Stride and cap.** For each layer maintain seven states. State r holds the minimum and maximum number of qualifying hot samples in earlier scan positions conditional on r prior survivors modulo seven. Initially only residue zero is possible. At an uncertain boundary a particle can retire (leave the state alone) or survive. A survivor increments the residue; when the previous residue is zero and the cooled particle is hot it also increments the sample count. At the next layer reset the residue, carrying the extremal sample counts forward. Min/max are sufficient for the <cap and ≥cap predicates. The permitted survival paths overapproximate correlated native motion. At a given carrier, the predicate recognizes possible service when residue zero is reachable below capacity. Guaranteed service requires certain survival, no other reachable residue and maximum prior samples below capacity.
3. **Heat.** For a recipient, the nearest and farthest distances to a speed disk bound the decreasing native radial kernel. Use every possible serviced carrier for the upper sum and only the guaranteed ones for the lower sum. Iterate in native service order. Per-addition binary32 rounding is monotone. Inflating distance/addition bounds by 1e−9 covers binary64 operations on the coordinate and parameter ranges of the two workloads. Ignition uses the same native decay and rounded comparison as the full update. An earlier crossing of the lower bound during the sum is already sufficient for a yes because all remaining increments are nonnegative. Graph donations after the last scan have no effect on the current query. All recipient states and fuel are fixed before this scan.
4. **Horizon.** A yes at the next scan resolves a longer existential query at its earliest possible frame. A one-scan no resolves the horizon only when H=1. Other cases defer to a real native query from the unchanged starting state.

The ordinary all-hot comparator performs the same survivor/thermal/spatial filtering but permits every possible surviving hot carrier, ignoring stride and prior sample capacity. Accumulation still follows Morton order. It lower-bounds only the residual stored heat. Both rules are one-sided. The cost and correctness of a two-sided native query require the fallback measurements in the browser.
