# The native scene has a second material subsystem

Before any T154 device call, source inspection falsified the assumption of absent object-temperature dynamics in the initial registration. The released fire preset contains a stand and a curtain, so ObjectHeat.wanted returns true. The native engine steps their skin/core temperatures and thermal contact clocks once per frame. Previous gas readback alone cannot establish the equality of this state. The original gas-plus-embers-only restore is insufficient. This narrower supported fire-only contract adds the exact native state to the already registered test. The device, alternative parameters, proof bound, byte-matching rule and budgets stay fixed.

At each target boundary preserve the native float64 [skin, core, ground-contact duration] array, per-pair contact durations and the list of last-frame radiant sources read by ObjectHeat.sample. No liquid, matter, separate rigid simulation or fabric may participate. Require the heat-exchange debt arrays to be absent and the radiant accumulator to be zero. Save the radiant grid, cleared/built flag, native count and its ordered live-source bytes. The unreferenced tail of the source list, the temporary per-cell RT and OB, and ObjectHeat.last diagnostics are not future inputs. The next frame computes surface sample locations and temperatures before replacing OB, and rebuilds the complete RT/RL list from gas and objects. An upstream ordinary reset does not invalidate Radiant.built: restore the cold initial metadata before each independent path so the previous simulation's radiant sources cannot enter its first frame. Compare the augmented state between native ordinary, fork, saved and restored futures at all registered boundaries. Check the overlapping T151 gas/ember inventory separately at frame 36. No empirical outcome or new native trajectory existed when this clarification was recorded.
