# Why these two native feedback grids drive the same gas hooks

This is a post-hoc explanation of the T131 frame-1 and frame-2 reference grids. Their 302 changed integer words fall into two velocity channels. The registered test still fails on these bytes. This audit asks what each hook would do if given the same finite gas input, uniforms, shader, texture format and enabled hooks. [Registered protocol](../effective/PROTOCOL.md) · [Capture receipts](../evidence/reference.json)

| Velocity component | Changed words | Frame 1 skip / add zero | Frame 2 skip / add zero |
| --- | --- | ---: | ---: |
| X | 0 | 9,537 / 0 | 9,537 / 0 |
| Y | 132 impulse | 9,537 / 0 | 9,537 / 0 |
| Z | 170 projected area | 7,412 / 2,125 | 7,412 / 2,125 |

**Y impulse is recorded on an axis with zero projected area.** The shader interpolates area, area-weighted cloth velocity and impulse separately. It skips an axis when interpolated area is nonpositive. On frame 1, 1,525 Y-face stencils have a positive-weight corner with nonzero impulse. Every one of them skips. Frame 2 has no such impulse. On Z, the two grids have the same occupied cells and zero impulse throughout. They take the same branch at every face. Wherever the area is positive, both add zero to the incoming velocity even though their areas can differ. [Pinned velocity hook](https://github.com/gjnail/blackbody/blob/e2ac951dbfabc6060073943e4c344439ac5f4555/blackbody/engine/wgsl/cloth_air.wgsl#L21-L80)

The sufficient test accepts an axis if both grids have identically zero area, if both have zero impulse with identical positive-area support, or if their three input channels match. It requires nonnegative area and equal fuel, heat, smoke and steam source words. The scalar/steam shaders then read identical values at every corner. Native hook activation, dry/wet state, layout, flags and step parameters must match when applying this argument. [Scalar hook](https://github.com/gjnail/blackbody/blob/e2ac951dbfabc6060073943e4c344439ac5f4555/blackbody/engine/wgsl/cloth_feed.wgsl) · [Steam hook](https://github.com/gjnail/blackbody/blob/e2ac951dbfabc6060073943e4c344439ac5f4555/blackbody/engine/wgsl/cloth_steam.wgsl)

The CPU enumeration includes all components written to the full 17 × 33 × 17 velocity texture, including the 1,345 texels on one or more upper boundary planes. It reads 13 signed words per cell with X fastest, applies the staggered offset for each axis, and treats out-of-range corners as zero. With a 2:1 cell width ratio, interpolation weights are nonnegative multiples of 1/64. An occupied corner with positive weight contributes at least 1/64 to area. This makes the integer support enumeration exact for the native branch on this grid. Zero impulse on an active stencil produces the same zero addition on both paths, including for an incoming signed zero. Eliding the hook entirely can instead preserve a negative zero, so this analysis does not establish that general optimization.

Run `python -B audit.py` from this directory with NumPy installed. The script verifies the capture hashes and compares every branch. Three in-memory changes each cause rejection (a scalar source, Y area in an impulse cell, and Z impulse in an occupied cell). An isolated Y impulse change with globally absent Y area still qualifies. The receipt records those controls and both buffer hashes. No new device run, held-out edit, compression benchmark or alternate continuation was performed. The result applies to these hooks and the common-input comparison. It does not compare two full trajectories or qualify a reusable edit. [Code](audit.py) · [Recorded counts](RESULTS.json)
