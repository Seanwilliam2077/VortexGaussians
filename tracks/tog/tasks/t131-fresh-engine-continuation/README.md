# Cold checkpoint continuation on the neutral Blackbody fixture

T131 tests what a new process recovers from the native frame-1 disk checkpoint. The reference simulates one frame of unheated hanging fabric with no emitters, saves it, and continues to frame 2. Two new Python processes each open the same file read-only and restore frame 1. One continues immediately. The other restores the saved cloth-to-gas feedback into its native buffer before continuing. Any attempt to simulate during the disk lookup raises an error. The fixture uses 1,470 cloth vertices, a 16 × 32 × 16 gas domain, 24 fps, and the same released source and D3D12 adapter as T130. [Primary protocol](PROTOCOL.md) · [Auxiliary native re-splat protocol](REBUILD_CONTROL.md) · [T130 fixture and runtime](../t130-independent-fx-choice/preflight/README.md)

**The native cold start dropped a real pending input, yet frame 2 still matched the uninterrupted result.** Both fresh restores recovered all recorded gas, cloth and ember fields at frame 1. They loaded no feedback buffer, had no coupling dimensions and marked the buffer unready. The uninterrupted frame-1 buffer contained 324 nonzero words out of 13,312, across 8 × 16 × 8 cells. Supplying its original bytes, layout and ready flag restored all measured parent state exactly. Both workers then agreed with the uninterrupted frame-2 reference across all measured fields and metadata. That reference grid had changed in 302 words since frame 1. The native re-splat recovered 12 channels exactly. All 132 mismatches occurred in channel 10, the y component of accumulated momentum. The fresh engine's 23,520-byte per-vertex impulse buffer contained only zeros before re-splatting. The shader reads the impulse and clears it on every splat. Complete recovery of this pending field and a change in the measured continuation are separate experimental outcomes. ## Cost of the controls

The single native disk checkpoint occupied 52,025 bytes and had the same SHA-256 digest on all three workers. The supplemental format used 53,248 raw bytes plus 311 bytes of JSON, totaling 105,584 bytes with the original native checkpoint. Single measurements for saving the supplement were 0.871 ms to read the GPU buffer and 0.716 ms to write its raw file and metadata. Loading, validating, allocating and submitting the GPU copy took 1.320 ms, followed by a 0.636 ms verification read. Native disk lookup and restore took 4.166 ms in the ordinary process and 4.661 ms in the supplemented process. These clocks use the actual raw sidecar. The lossless NPZs distributed for audit have a different encoding. [Reference receipt](evidence/reference.json) · [Supplemented receipt](evidence/supplemented.json)

The three full worker times were 94.16 s, 67.61 s and 78.37 s, in reference, ordinary and supplemented order, each below the registered 180 s cap. Constructing and preparing their engines consumed 90.80 s, 64.18 s and 74.50 s respectively. On the third process's warmed device, preparing and verifying the separate reconstruction engine took 209.54 ms. The native re-splat including the synchronized full-grid readback took an additional 1.093 ms. Times are single observations, with process startup, pipeline preparation and synchronization charged to their respective phases. ## What was measured

The archives preserve the packed gas velocity, scalar and pressure fields and the cloth X, P, V, S, N, W and MP fields. JSON also preserves gas layout and clocks, cloth step count and identity, the ember count, and the feedback flags and dimensions. Every available feedback grid is stored losslessly. A frame agrees only when all observed fields and metadata agree. This fixture supplies no evidence about burning cloth, artist preference, or final rendered output. [Raw state receipts](evidence/) · [Native cloth checkpoint fields](https://github.com/gjnail/blackbody/blob/e2ac951dbfabc6060073943e4c344439ac5f4555/blackbody/engine/cloth.py#L1153-L1178)

The native disk blob and supplemental transfer files lived in a temporary directory, which closed after the last worker exited. The native byte count and digest, all supplemental metadata, and the complete measured arrays remain public. The operator below creates a new native checkpoint from the neutral scene and checks within each run that all workers use identical bytes. The accompanying offline analyses document the interpretation of the physical feedback. ## Reproduce

Run `python verify.py` here in a Python environment with NumPy to compare all numerical archives, including the reconstruction when available, without a GPU. `python verify.py --output OUTPUT.json` writes the same summary. For a new device run use `python run.py --source BLACKBODY_CHECKOUT --out NEW_DIRECTORY` with the T130 runtime, exact Blackbody revision `e2ac951dbfabc6060073943e4c344439ac5f4555` and the admitted NVIDIA RTX 5070 Laptop GPU. The operator requires a new output directory, uses one temporary native cache, and schedules workers serially. Rebuilding on the already initialized third device starts only after all three primary outcomes are stored.
