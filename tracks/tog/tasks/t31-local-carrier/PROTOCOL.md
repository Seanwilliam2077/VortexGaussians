## Input qualification gates

Both snapshots must have the prescribed frame/time, mode/config/optics, nonempty particle arrays with counts matching declared physics/render totals and count<=600, finite x/y/z/T/d, d>=0, no render override and positive aggregate optical strength. Explicit particle weights must be finite and nonnegative; missing weights mean1 for shared3d. Physics and render arrays must match except the snapshot-added id. Time equality to frame/60 and aggregate density/temperature/optical-density equality use abs(a-b)<=1e-10*max(1,abs(a),abs(b)). Every new Gaussian has finite mu/color, h>0 and k>=0. Its stored color is the exact declared formula applied in JavaScript binary64, not a bitwise GLSL float32 reproduction. All intended steps, snapshots and source identities must match; unexpected browser page errors or external requests fail qualification. Camera distance/elevation/FOV and emission must be finite, camDist>0, abs(camElev)<pi/2 and0<fov<pi, making the right basis nondegenerate. A single replay does not establish general deterministic replay, physical fidelity, or renderer accuracy.

Qualification means a reusable authored input exists. It does NOT mean the ordinary full-frame renderer is ready, that a bottleneck exists, or that this is a valuable/new method. If qualification fails, stop and report the cause without a replacement run. If it passes, only a separately frozen ordinary-reference entry task is eligible: implement a same-field ray adapter, conservative culling, and an ordinary accuracy-controlled integrator, then establish its correctness before any complete-frame cost claim. No T29/T30 formula, new candidate renderer, larger population, or full benchmark is automatically queued by this protocol.
