# Can the regional material dependence remain local under fair graph service?

Freeze before calculating graph connectivity. Inspect the existing native scheduler in `demo/index.html` and archived P1/P2 controls. No native graph rotation is implemented. The P2 research suite already offers effectively unlimited graph work with `spreadFrontierCap=1000000`; every current burner is then visited on all three scenes. Consider transferring this existing cap to the current physical editing fixture under the same kernels, ordinary round-robin emission and clocks. It is a different material service configuration of the same solver, not a second solver or a run of the full authored-area P2 model.

In that configuration a newly ignited site can deposit on graph neighbors in the same step, testing those recipients at the next ignition scan. A conservative backward geometric dependency set for H scans is the full geometric shell and every site at up to H−1 radius-neighbor hops. Native gas still comes from the entire scene. Source-ID stability for the emitter remains a separate requirement. A component disjoint from the shell cannot reach it by graph edges. Dependency membership alone does not establish ignition, a qualified emitter horizon or a speedup.

Use all original material positions from Firewoods, Dead Tree Trunk and Playground at the prior recipes, same two 0.12-radius second clicks at frame 180, 0.14-wide exterior shells and 0.11 source-space graph radius. H=60 and 180 on the two development scenes, H=30,60,180 on Playground. Use geometry only, without labels or downsampling, and without inferring changed-scheduler thermal state from capped-scheduler cuts. Include every material point in the geometrical shell to cover arbitrary viable recipients. Report exact radius-connected component populations hit by each shell, exact counts at each hop and the maximum number of hops traversed. Record mean active predecessor count across shrinking reverse-time slices as well as unique support. Also upper-bound component diameter by double the BFS eccentricity of one fixed representative, for interpreting a nonempty subset of eligible sites.

Use a uniform spatial hash and FIFO multiseed BFS with native binary64 distance checks. Count all nonzero-heat graph edges (`d² < r²` and `sqrt(d²) < r`); native enumeration allows equality, but exact boundary weights are zero. Retain index order for site identity. Verify against brute force on a small deterministic set including boundary cases. Check input SHA-256, shell IDs/count by independently available archived labels, and invariants connecting the two BFS reports. A 180s wall deadline and up to one billion distance checks per asset bound the static study. A resource failure stops the corresponding measurement.

If most (at least 75%) of the full scene is in the initial H−1-hop domain for a majority of registered queries and fewer than two distinct edit arms have both support and mean space–time fraction below 50%, stop this simple geometry-only route without native timings. Otherwise publish the eligible conditions first and decide a separate native experiment. Include minority and unfavorable results, and short-horizon counts, with no post-hoc changes to radii, stop gate, sites or edit ordering. This static task does not exclude a better state-dependent bound or establish a runtime improvement.
