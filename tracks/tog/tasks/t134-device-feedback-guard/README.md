# Comparing two resident cloth feedback grids

The corrected two-dispatch GPU predicate matched the frozen rule on all 19 correctness pairs and all 450 measured calls. On two real, unequal 1,024-cell feedback grids the GPU took a median 186.9 µs versus 192.5 µs for the batched CPU. The GPU won only six of 15 matched blocks. The larger repeated grids favored the GPU in every block. [Verified score](recovery/evidence/score.json) · [Raw clocks, actual returns and initialization costs](recovery/evidence/measurements.json)

All times above are warm host wall-clock medians. Each CPU call reads 106,496 or 6,815,744 bytes. Each GPU call reads four bytes. Setup on the RTX 5070 Laptop GPU took 2.637 s for admission and device creation, then 92.1 ms for construction of the three corrected pipelines and associated buffers after diagnosing the original implementation. Per-pair buffer allocation, upload and synchronization took 0.393–1.280 ms. A separate first call per method and pair precedes the 15 measured blocks; all its costs are archived. The 65,536-cell controls repeat the same neutral array contents 64 times. They measure resident comparison at a larger byte count. Timing a live action requires costs for reaching these inputs, verifying gas-side prerequisites, evaluating subsequent steps and returning the artist's requested result.

The T130 frozen test compares the 13 signed integer channels of two cloth feedback buffers. A caller supplies two complete Blackbody GPU buffers of equal length after qualifying the external gas forcing, clocks, material state divergence, native flags and compatible grid layout. A raw match gives the original equality rule. The additional rule admits certain different words when all scalar sources match and each velocity axis has at least one globally valid reason for equivalent gas coupling. The first native implementation combined workgroup facts using atomic OR and returned a four-byte decision. Its 3.82 s worker passed the first pair and rejected two copies of the same recorded frame in the second correctness check. The native full and raw entries both returned a difference. The registered stop prevents timing this implementation. [Initial protocol](PROTOCOL.md) · [Actual exit and error](evidence/measurements.json) · [Failure verifier](verify.py)

That failure reproduced on a fresh device. Both input readback hashes matched their intended buffers. After the first full call stored 19,072, a raw comparison whose only valid difference word was 1 stored 19,073. Both subsequent calls on equal buffers still stored 19,073. Direct storage readback confirmed the stale bits, and a standalone command successfully cleared a deliberately nonzero result to zero. This isolates the symptom in the earlier reduction/clear sequence. The experiment cannot determine the responsible backend operation. The recovery checked each explicitly overwritten partial and final word against an independent CPU reduction in all 19 cases, including the failing pair. [Original and corrected diagnostics](recovery/evidence/measurements.json)

The separately registered recovery checks the earlier kernel's stored answer and inputs, then evaluates a two-pass implementation. Each workgroup overwrites its partial result and the final workgroup overwrites the decision. The CPU control uses one preallocated mapped staging buffer for both complete input buffers, makes one ordinary copy submission, and classifies the mapped words in place. It tests raw equality with native libc memcmp. The device path copies its four-byte answer to preallocated staging in the same native batch as its two compute dispatches. The original two-read CPU implementation is a second transfer baseline. Run `python verify.py` in this directory with NumPy to verify the initial failure. After a registered recovery run, `python recovery/score.py` checks input digests and every recorded control and timing inventory against the archived fixtures. Reproduce the device measurement in a new output directory with `python recovery/run.py --source BLACKBODY_CHECKOUT --out NEW_DIRECTORY` using the pinned T131 Python runtime. The two-pass guard returns one of `raw`, `axis` or `split` from `ResidentGuard(gpu).compare(first, second)`; a live caller should keep the comparator on its existing device for repeated sequential calls. The return covers feedback words only.
