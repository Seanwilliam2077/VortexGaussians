# T124 · Native Blackbody preset loads, first device initialization fails

We loaded both frozen versions of the official `fabric_curtain` shot with the unmodified Blackbody Python scene parser. It returned the native 160-resolution cotton preset with frames 1–264, its camera and the requested lighter dimensions. The source-only package contained 442 Python/shader files totaling 4,981,459 bytes, without its assets directory. Python 3.12.14 already had NumPy and cffi; wgpu 0.32.0 and rendercanvas 2.7.2 were isolated outside the repository. No downloaded Gaussian asset, OBJ, footage, preset thumbnail or third-party package appears in the published evidence. [Both source-only scene receipts](evidence/PREFLIGHT.ndjson) · [Pinned upstream code](https://github.com/gjnail/blackbody/blob/e2ac951dbfabc6060073943e4c344439ac5f4555/blackbody/scene/presets.py#L450-L476)

The light-arm worker entered `Engine()`, then Windows terminated it with `0xC0000005` (decimal 3221225477). A corresponding application error event identified `atio6axx.dll`, version 32.0.23027.2005. The program never returned an Engine object so the specific selected adapter, stage within its constructor and original driver fault remain unknown. It sampled zero gas/cloth frames, produced zero final images, and stopped before attempting the full arm as registered. The driver observation supports a separate graphics backend admission check. It gives no flame result, no proof that the two emitted states are equal or different, and no external speedup. [Interrupted light-arm checkpoint](evidence/native/L.json) · [Worker exit](evidence/native/SUMMARY.json) · [Sanitized operating-system event](evidence/WINDOWS_EVENT.json)

The native API exposes vertex thermodynamic state, grid density/temperature/velocity, checkpoint/restore and separate scene-linear emission/composite outputs. Its camera-space output would answer a more direct visual question than the former Gaussian surface proxy. Access to these live buffers on this host remains unverified.
