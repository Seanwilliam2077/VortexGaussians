## What reaches the client

The sequence covers frames 225–254 at native 60 Hz, totaling 59,558,400 bytes. The host receives the complete uncompressed stream and a browser-side handle that still owns the frame-254 simulation. Delivery ends when both are available. Every measured transaction compares its host buffer byte for byte with the fresh native oracle **after** stopping the clock. Audits also compare the five full material arrays, ordered gas particles, frontier, clocks, RNG and related state at acceptance. The separate continuation request checks the retained endpoint and one further ordinary update. The public receipts contain every frame digest and the physical digests. Rebuilding frames requires the original fit and renderer. No participant selected or watched the take.

The ordinary native oracle independently evaluates the target after each complete native step. It tests the changes of originally cold target sites using the calibrated per-site mass. The optimized methods count those changes during the scan. Ordinary kept the crossing state live. Chronological repair logs the partial interval needed to resume material and may discard its final projected block. If that final block unexpectedly accepts a candidate, this implementation physically reconstructs the winner from its parent. The hybrid method screens light regionally and uses direct indexed stepping on the heavy stroke, so it can keep that take directly. The sibling method holds the eligible light checkpoint, reconstructs the heavy branch at +24, and executes the remaining 20 steps to the crossing. Light's prior deadline miss cannot certify heavy's result because they cross the queried surface at different times. All methods receive the same parent, immutable camera weights, cold-recipient geometry, and callback-free native rendering. A client permitted to reuse an identical previous request could cache the answer and take on either backend.
