# Why the material state can be recovered without replaying the gas

The reference is the repository's floating-point, ordered JavaScript operator under the frozen T86 controls. At each frame it advances the gas, samples hot carriers in native order and deposits heat, applies material decay and tests ignition, transports heat on the old frontier, updates fuel/glow/charring, and emits gas from a capped service queue. The query asks for the first newly ignited monitored site; an arbitrary witness at the first frame is sufficient. Its answer can be used before any unobserved material values have been reconstructed on the disposable branch.

Let the old burning list have length `n`, the current service cursor be `c` and the per-frame feed cap be `b`. For a prefix of `L` intermediate frames, the guard requires `c + L*b < n`, an already saturated donor cap, and positive remaining fuel for every old burner through the entire prefix. The fuel condition explicitly repeats the native binary32 subtraction from the minimum old fuel. The comparison is strict to avoid crossing the moving queue boundary. Other eligibility conditions, including the source mode and timestep, are in T95. The implementation chooses the largest qualifying prefix subject to the remaining query horizon.

* The active graph donor IDs remain the same ordered initial prefix. Newly ignited sites append beyond that donor cap, and all old donors survive. The emitted source IDs likewise remain the original ordered services because no wrap, removal or cursor-dependent substitution occurs. The regional branch therefore generates the native gas particles and consumes the same random draws.
* For each monitored, initially unlit site, the regional gas deposition and graph additions keep the native order and binary32 rounding. The spatial reject encloses all monitored positions, with the native support radius plus padding. By induction through each event-free frame, its heat and first crossing agree with native evaluation.
* For every guarded block that could expire before the terminal query frame, the repair operator saves the initial full material and stores each sampled gas position in source coordinates together with the exact binary64 carrier temperature, before regional rejection. If the guard expires without an event, the reconstruction deposits from these records on all eligible sites and performs the full ordinary graph, fuel, glow, charring and ordered frontier steps in the native order. It restores each recorded cursor. It does not call the gas or random operators. Frame-by-frame the reconstructed state has the same inputs as the ordinary full material transition. The next gas update receives the fully reconstructed material state and the already advanced native gas.
* A zero-length guard costs one ordinary step and a new qualification. The final step can use the exact rank-only output operator from T93. A detected first event can end a disposable branch immediately; this T100 interface returns only an answer and cannot keep that partially updated branch as an authoring state. T103 separately studies retained edits.

The exactness argument concerns the frozen discrete reference, including its caps and iteration order. It makes no claim about real combustion, arbitrary source modes, or error relative to a continuum model. The native repair audits compare every byte of every material array, ordered frontier and cursor, RNG, source, pointer, ember and gas state at an actual guard boundary and after one further native step. Independent T102 audits compare complete states for eight steps after each second click on every asset. Timing trials run before the per-arm untimed audits to avoid audit warm-up, and the scorer accepts the receipt only after both the timed reference checks and the audits pass.
