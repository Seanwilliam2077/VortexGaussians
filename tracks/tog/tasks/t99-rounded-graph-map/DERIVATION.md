# Parity-preserving translation within a normal binade

Model one native update as `y = round32(round64(h + d))`, where the stored input is binary32 and each already computed graph increment d is finite, nonnegative binary64. RN uses round-to-nearest ties-to-even. In the source, heat is a Float32Array and the product for each increment is evaluated by ordinary JavaScript arithmetic. A batch of donors arrives in a fixed order. The contract includes the per-write rounding.

Fix a normal positive binade with lower endpoint B and binary32 spacing u=B/2^23. Inside it the binary64 spacing is u/2^29. Translating an incoming binary32 word by any even number of u leaves the low bit of its binary32 significand unchanged. The inner binary64 addition also commutes with that translation: even one u is an even number of binary64 units. Thus, as long as both exact sums stay inside the same binade, *both* roundings commute with translation, including exact halfway cases for either precision. This includes cases where binary64 rounds an addend effectively to a binary32 midpoint before the binary32 write.

For each donor sequence and requested binary32 exponent, evaluate the full serial recurrence twice, at B+2u and B+3u. Record the output minus input in units of u for each parity. The implementation rejects a probe that spills or reaches the uppermost word of the binade. On a query, select its parity and charge the recorded shift only when the query starts above B and the predicted endpoint has at least one internal grid word before the upper boundary. Nonnegative increments make the intermediate rounded words nondecreasing, so a safe endpoint contains all earlier translated words. More precisely, each pre-round value differs from its rounded representative by at most half a binary32 step plus half a binary64 step. The strictly interior upper guard prevents a translated addition from crossing the binary64 binade boundary in advance of the binary32 rounding argument. Positive additions also keep the unrounded translated lower endpoint at or above B. Induction then proves that every intermediate query result is the translated representative result. Finally use the exact binary32 word addition to return its translated endpoint, with no approximate floating multiply.

A sequence of half-ulp increments shows why parity matters: adding half a unit can preserve an even significand or advance an odd one. A single pre-summed coefficient rounds at a different time and need not equal the serial operator. Any boundary/subnormal/overflow case that fails this test takes the original serial path. Signed deposits, changing order/weights, diffuse operators with negative adjustments and different floating-point environments are outside the contract.

The cost tradeoff is explicit. A fresh descriptor uses two native serial reductions for the donor list even if its first query later spills. Reusing the same descriptor can amortize that cost only for the same ordered increments and exponent. Geometric adjacency alone does not guarantee that the dynamic serviced donor list is identical across edits. Two consecutive queries at different heat magnitudes can also need different exponents. The benchmark records actual frontier identities rather than assuming reuse from a common scene name.
