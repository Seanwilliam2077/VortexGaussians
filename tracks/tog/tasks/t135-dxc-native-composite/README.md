# The installed DXC compiler rejected a shader-module name during engine construction

In T132 the default FXC renderer reached the classic stage pipeline. Here the pinned wgpu runtime explicitly selected the Microsoft SDK DXC compiler on the same NVIDIA D3D12 adapter. Its expected DLL loaded. The native DXC worker reached engine construction at +2.210 s and returned an error at +2.484 s while compiling `light_emit.wgsl:main`. It never reached the stage or restored a frame. The full process took 3.022 s. The earlier 0.511 s pre-device logger initialization failure has [separate receipts](RECOVERY.md). [Protocol](PROTOCOL.md) · [Native compiler selection](native-evidence/COMPILER.json) · [Exact engine error](native-evidence/RESULT.json)

Using the same SDK's CPU compiler API and a fixed, in-memory HLSL program, the source-name argument `light_emit.wgsl:main` reproduced the read error. Using `light_emit.wgsl_main` or omitting the name produced the same shader binary, SHA-256 `a05263b04da8780c6024399afd60976c84c744d774a6709ed4116261addf6137`. This test isolates the name for the small HLSL program. T138 tests label substitution on Blackbody's full original shaders.
