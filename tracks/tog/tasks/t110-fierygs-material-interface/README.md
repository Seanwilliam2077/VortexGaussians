# A second fire solver has a one-way material interface

The released FieryGS Firewoods grid solver already admits a simpler exact ordinary baseline for a disposable ignition query. Its wood-temperature kernel reads only the current solid temperature, the occupied face neighbors, local diffusion/cooling coefficients and a temperature threshold. The occupancy kernel reads wood temperature and a fixed noise field. It can write the gas source coefficient when material is exhausted, but it never reads the gas state to update material. The gas uses the wood result in its coefficient update. Consequently an ordinary implementation can advance all material to answer a wood-ignition question without advancing gas, velocity or pressure. This also applies when depletion is active under the same upstream code. An editor requesting the gas image or a complete future incurs the cost of that additional output. The referenced 128³ CPU take is a previously executed run of the released numerical kernels with a headless adapter, Firewoods configuration and burn rate zero. All five archived occupancy arrays coincide bitwise. Only 5,542 of 2,097,152 grid cells are occupied (0.264%). Among those cells, 1,131, 1,208, 1,495, 2,624 and 4,700 reached the native wood threshold at steps 0, 3, 10, 30 and 60. The footprint divides into 163 face-connected components. One contains 5,322 cells (96.03% of the occupied domain); the next largest has 15. For a selection inside the main wood body, omitting every other component saves at most 220 occupied cells per substep over an ordinary compact material solver. A selection touching a tiny isolated fragment would be a different workload.

This separate published solver establishes an important limit on the technical claim. A speedup against its complete fluid solve would primarily demonstrate the existing one-way material dependency. It cannot demonstrate a certificate for two-way feedback. The archive contains a single original trajectory and five checkpoints; it supplies no new edited-shot latency. The local experiment used only existing files. No upstream asset or third-party implementation is redistributed here.
