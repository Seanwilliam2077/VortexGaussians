# Can a valid DXC module label deliver Blackbody's original final image?

T135's actual DXC process stopped during engine construction while compiling `light_emit.wgsl:main`. In a subsequent CPU-only test using the same SDK's IDxcCompiler3, the original source-name argument reproduced the same read error. A filename-safe underscore and omitting that argument both compiled the same in-memory test shader to byte-identical DXIL. The affected wgpu HAL puts a module's diagnostic label in the DXC argument list in addition to the in-memory HLSL. This motivates one specific change. [Controlled compiler call](../t135-dxc-native-composite/compiler_labels.py) · [HAL compiler arguments](https://github.com/gfx-rs/wgpu/blob/v29.0.1/wgpu-hal/src/dx12/shader_compilation.rs#L337-L395) · [HAL source name](https://github.com/gfx-rs/wgpu/blob/v29.0.1/wgpu-hal/src/dx12/device.rs#L381-L390)

Before a new GPU call, fix the sole intervention to replacing colons with underscores in optional WebGPU shader-module labels. Record the original and submitted labels and source SHA-256 for every affected module. The WGSL text, pipeline label, shader key, entry point, binds, options and renderer remain those of T135. Require the original main and caustics stage keys, the signed SDK DXC library, the recorded frame-2 physical state and the same final 320 × 180 linear readback. Record complete wall time including staging and readback. One new 300 s worker, with the same deadline supervisor, one final composite and no artist candidates. Archive any partial result. If delivered, no FXC composite from T132 exists for a pixel comparison.
