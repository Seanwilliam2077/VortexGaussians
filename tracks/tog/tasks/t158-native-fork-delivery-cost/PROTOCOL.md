# Fixed-output cost of two native curtain takes

T151, T153, T154 and T157 and their numerical outcomes were known at registration. Use exclusively the released curtain preset and its fixed 0.35/0.70 s catch-time edit on the same Blackbody pin, NVIDIA D3D12 device, final-quality solver, camera, frame rate and zero preroll. The task is investigator-defined. It asks whether a supported ordinary shared-prefix implementation reduces the wall time to deliver *both* alternatives under the same output contract.

**Output.** From a ready device, prepared engine and two scene definitions, deliver two fresh native frame-36 checkpoint files with the same metadata, complete gas, atlas, ember, contact and thermal/radiant feedback as T154. For each arm include common scene reset, stepping, device readback, checkpoint serialization to a unique local filename, atomic save, and a host reread of the complete file that matches its SHA-256 to the corresponding retained T154 packet. File presence and matching bytes establish equivalence to the packets independently resumed at 37 in T154. T158 does not perform a new step to 37. No previously simulated frame, derived slow state or reference digest may supply future dynamics or select the split. Do not cache endpoint payloads. File writes use normal OS caching with no explicit disk flush. Bound local output to 2 GiB and require 3 GiB free before each process. Retain packets privately.

**Three paths.** I runs each original solver independently from its initial state. D runs one gas during the T151 certified whole-frame prefix with two real native surface atlases. S runs a single fast atlas and dispatches the T157 ambiguity test on-device after every admitted update, including a check on native initialization. Accumulate errors across the complete history, then read the count once before a slow state is demanded. Before each common frame D and S use the live CFL schedule and T151 bound, with the same preconditions. If S ever encounters a negative, nonfinite, saturated or ambiguous word, retain its valid fast trajectory and run the native slow arm from its original beginning. An admitted S fork creates the slow atlas by halving the native stored catch channel. Diagnostics outside timing never authorize skipping the in-timer checks. Report whether the actual workload exercises fallback. As a separate one-time device admission, test both the classification and reconstruction against CPU half words and require conservative unsafe handling. Charge the cost of this shader compilation and admission separately as S-specific setup, as well as showing first-use amortization. A failing implementation does not earn a timing win by returning the wrong output.

D and S have identical fork/restore scaffolding. Prefer an on-device checkpoint using the upstream carried gas textures and the full native state of both static thermal objects and previous-frame radiation. The layout and fields are fixed by T154. Store the slow atlas beside the checkpoint, retain the live fast arm, produce its packet, reset the same engine and copy the checkpoint back for the slow future. Account for allocation, memory footprint, copies, counters and synchronization. I requires no inspect-at-fork, copying of unused prefixes, or extra method. If memory cannot hold the declared device checkpoint, record the failure; the prior host strategy remains documented separately. These are three ordinary algorithms. A faster one does not establish a novel general editing method.

**Design and budget.** Two fresh, serial device processes. In each, measure three consecutive matched blocks. The orders are IDS, DSI, SID in process 0 and SDI, DIS, ISD in process 1. Each method occupies each within-block position once per process. Each measured cell starts at the request before its first reset, with the same supported blank scene contract, and ends at the second packet's verified host read. Use precompiled native pipelines for the available worker; an identical one-time unmodified practice step or prefix to warm normally lazy native kernels may be performed for all paths, must be charged to process setup and must not supply any state to a measured cell. Time scene resets, native prefix/suffix, fork capture, restoration, host checkpoint readback, serialization and full verification. Expose shared cold device/engine cost, S-specific admission, repeated request times, conditional first-request cost, per-arm raw/compressed bytes, and complete worker wall time. Per process limit 720 seconds including cold start and controls. Attempt each process once. Stop on numerical, device, storage or clock failure, publish the first incomplete block and its diagnostic. No additional rounds or changed workload.

**Decision.** Report each paired difference and ratio, each worker's medians, aggregate median paired improvement, and favorable paired counts. A repeatable directional benefit requires lower median delivery cost in each independent worker and at least five of six matched blocks. Label a practical benefit only when median paired relative improvement also exceeds 3% across all six blocks. Compare D and S to I, and D and S directly in both directions. A path must satisfy the rule against both alternatives to be the overall winner. Differences outside these rules remain inconclusive. Report speed signs with and without one-time method-specific setup, separately from the repeated ready-engine contract. The sample is one known edit and device. No inference about author preference, arbitrary catch-time ratios or submission readiness follows.
