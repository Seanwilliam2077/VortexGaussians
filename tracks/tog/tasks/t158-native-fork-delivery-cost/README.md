The shared cases use the same GPU checkpoint implementation for the gas and prior-frame radiation. It copies the coarse and fine gas, pressure, velocity, floor surface, alternate object atlas, radiation accumulator, counts and packed source list. The host retains the material temperature and contact clocks, simulation counters and ember bookkeeping. Only the fast arm stays live. After delivery of its packet the implementation resets the engine, copies the branched state back and produces the slow packet. This avoids a whole-fork host transfer that T154 used for its correctness observers. The observed retained device checkpoint occupies 541,012,320 bytes, including the alternate 520,128-byte atlas. D temporarily allocates a second 520,128-byte atlas for ping-pong updates. [Device fork and restore](fork.py) · [Earlier native/cold endpoint checks](../t154-native-surface-fork/README.md)

S dispatches the half-word check on the initialized fast atlas and after each admitted update. It accumulates a sticky count on the device. An invalid or ambiguous history leaves the fast simulation usable and makes the slow branch run natively from its beginning. An all-safe history needs one four-byte decision read, then a GPU pass halves the catching channel and copies the other three channels. The source-specific dry, unlit scaling premise and the certified no-emission bound restrict when this comparison is valid. It has no transfer claim for arbitrary catch-time ratios, ignition, water or moving solids.
