# T16 — semantic qualification of the acquired ordinary renderer

28 October 2026. **The inspected entry points do not supply a matching ordinary reference for T15 C's colored emission–absorption integral. Do not benchmark them as if they did.** The RF entry point composites peak-based opacity and SH color; the PRB entry point transports environment illumination through scattering/absorption. This source finding narrows what the acquired implementation can establish. It does not establish a new rendering contribution, disprove the paper, or rule out functionality in uninspected files or later versions.

## Scope and target

Read-only source review of author commit `622fabdac87aa446ca84131da97ebb9ac7d3d20c`, as supplied in the local acquisition directory `work/research-t16-source-audit/sources`. This review made no network request, installation, import, render, numerical execution or source modification. It read six complete Python files, the README and both dependency declarations. All links below pin the same commit and the cited line numbers were read from those local files.

The existing C contract is

```text
sigma(t) = sum_i s_i(t),       j(t) = sum_i s_i(t) c_i
T(t) = exp(-integral_0^t sigma(u) du)
L = integral_0^z T(t) j(t) dt + T(z) L_background,
```

with specified nonnegative Gaussian extinction, bounded per-component colors, linear radiance and a finite opaque boundary `z`. It does not include scattering or treat learned 3DGS opacity as a calibrated extinction coefficient. The audit checks that unchanged operation; it does not replace the baseline or invent a new rendering task.

The example selects CUDA/LLVM RGB variants, instantiates `volprim_rf` with `ellipsoidsmesh`, loads PLY and camera files, then calls `mi.render`: [example, lines 19–23](https://github.com/facebookresearch/volumetric_primitives/blob/622fabdac87aa446ca84131da97ebb9ac7d3d20c/examples/render_3dg_asset.py#L19), [lines 47–74](https://github.com/facebookresearch/volumetric_primitives/blob/622fabdac87aa446ca84131da97ebb9ac7d3d20c/examples/render_3dg_asset.py#L47). The inspected package imports additional utilities and tomography: [package imports, lines 6–16](https://github.com/facebookresearch/volumetric_primitives/blob/622fabdac87aa446ca84131da97ebb9ac7d3d20c/volprim/__init__.py#L6), [integrator imports, lines 6–10](https://github.com/facebookresearch/volumetric_primitives/blob/622fabdac87aa446ca84131da97ebb9ac7d3d20c/volprim/integrators/__init__.py#L6). Those additional bodies, `stack.py`, Mitsuba/Dr.Jit internals, shape loaders and camera implementation were not acquired for this audit. Their behavior remains outside the claim.

## PRB: overlapping extinction and scattering do not provide self-emitting colored volume

The PRB constructor sets `kernel_full_range=False` and `kernel_normalized=False`, defines an isotropic phase function by default and accepts overlap/depth/solver settings. Its `sample` method obtains an environment emitter and requires `sigma_t` and `albedo` attributes: [PRB 48–65](https://github.com/facebookresearch/volumetric_primitives/blob/622fabdac87aa446ca84131da97ebb9ac7d3d20c/volprim/integrators/volprim_prb.py#L48), [75–82](https://github.com/facebookresearch/volumetric_primitives/blob/622fabdac87aa446ca84131da97ebb9ac7d3d20c/volprim/integrators/volprim_prb.py#L75). The warning strings mention RF although they occur inside the PRB class; class membership and actual calls, not that label, determine this audit.

Its overlap mechanism is substantive: `primitive_tracing` keeps active primitive IDs, orders boundary events, clips a segment at an encountered surface and invokes a callback. [common 375–391](https://github.com/facebookresearch/volumetric_primitives/blob/622fabdac87aa446ca84131da97ebb9ac7d3d20c/volprim/integrators/common.py#L375), [468–515](https://github.com/facebookresearch/volumetric_primitives/blob/622fabdac87aa446ca84131da97ebb9ac7d3d20c/volprim/integrators/common.py#L468). `sample_segment` sums `sigma_t*density_integral` over that active set, exponentiates the negative sum and samples a medium distance. [PRB 513–557](https://github.com/facebookresearch/volumetric_primitives/blob/622fabdac87aa446ca84131da97ebb9ac7d3d20c/volprim/integrators/volprim_prb.py#L513). This supports overlapping extinction in a scattering path tracer, rather than simply sorting alpha layers.

However, reading the entire primal radiance dataflow gives a different source term from C:

1. A medium interaction multiplies throughput by the density-weighted `albedo`; it does not add emitted radiance. [PRB 154–159](https://github.com/facebookresearch/volumetric_primitives/blob/622fabdac87aa446ca84131da97ebb9ac7d3d20c/volprim/integrators/volprim_prb.py#L154), [435–460 and 510–511](https://github.com/facebookresearch/volumetric_primitives/blob/622fabdac87aa446ca84131da97ebb9ac7d3d20c/volprim/integrators/volprim_prb.py#L435).
2. The first primal `L` increment is environment radiance on an escaped path, weighted by throughput and MIS. [PRB 161–187](https://github.com/facebookresearch/volumetric_primitives/blob/622fabdac87aa446ca84131da97ebb9ac7d3d20c/volprim/integrators/volprim_prb.py#L161).
3. The other primal `L` increment is next-event estimation of that environment, multiplied by a BSDF or phase value and transmittance. [PRB 193–235](https://github.com/facebookresearch/volumetric_primitives/blob/622fabdac87aa446ca84131da97ebb9ac7d3d20c/volprim/integrators/volprim_prb.py#L193).
4. The remaining primal path updates sample the phase function or surface BSDF, update throughput and directions, and terminate/return. [PRB 237–301](https://github.com/facebookresearch/volumetric_primitives/blob/622fabdac87aa446ca84131da97ebb9ac7d3d20c/volprim/integrators/volprim_prb.py#L237).

Thus the inspected PRB forward path does **not** implement a per-primitive self-emission contribution `j=sum_i s_i c_i`. This conclusion follows from its complete radiance updates and called helpers, not merely from an unsuccessful keyword search. Setting a colored albedo makes environment light scatter with that color; it does not substitute for the prescribed emission. Setting albedo to zero removes scattered throughput and does not introduce a glowing source. The helpers also supply only `sigma_t` and albedo in `EllipsoidsFactory`: [common 566–596](https://github.com/facebookresearch/volumetric_primitives/blob/622fabdac87aa446ca84131da97ebb9ac7d3d20c/volprim/integrators/common.py#L566). This is a claim about these inspected routes, not every author implementation.

## Decision

**Matching author entry point among the acquired files: no.** RF computes a different alpha model; PRB supplies overlapping scattering/extinction without the required self-emission source in its inspected primal route. Absorption-only functionality named in the README would address transmittance, not by itself the missing colored-emission integral; its body was not read and is not claimed to fail.

**A worthwhile next timing or quality experiment for this unchanged candidate: not identified.** Measuring the RF/C difference would primarily reconfirm different semantics. Altering PRB to add emission would be new implementation work before a new mechanism has been specified. Neither the access gap nor a possible software defect justifies reopening T15 C or declaring a TOG contribution.

The mathematical ordinary comparator remains the already declared integration of the exact same `T*j` (and validated quadrature when a certificate is required). This audit found no acquired author implementation that can simply be relabeled that comparator. It does not establish that such a reference is unavailable in general. T15's generic-bound rejection stands; no new operation, substitute baseline, numerical fixture, performance claim or renderer-development task is authorized by this memo.
