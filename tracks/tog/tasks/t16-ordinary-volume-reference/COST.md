## Dependency and complete-cost boundary

The pinned [README installation section](https://github.com/facebookresearch/volumetric_primitives/blob/622fabdac87aa446ca84131da97ebb9ac7d3d20c/README.md#installation) requires a modified Mitsuba branch. Its [requirements](https://github.com/facebookresearch/volumetric_primitives/blob/622fabdac87aa446ca84131da97ebb9ac7d3d20c/requirements.txt) are unpinned, while [environment.yml](https://github.com/facebookresearch/volumetric_primitives/blob/622fabdac87aa446ca84131da97ebb9ac7d3d20c/environment.yml) specifies Python 3.11 but no exact Mitsuba/Dr.Jit revision. The example selects a CUDA/LLVM AD RGB variant before importing `volprim`. This does not establish compatibility with the local environment. The named external renderer branch, its current merge status, backend types and build were not inspected under this one-repository budget.

An eventual comparison must separately account for source/build qualification, one-time scene and acceleration-structure preparation, JIT compilation, any per-edit rebuild, actual rendering and synchronization, readback, output conversion and quality validation. Record first-use and repeated-use paths. Do not include one method's cold setup while excluding the other's, or report an example's rendering-only timer as complete cost. No timing, throughput, memory or speedup values exist for T16.

## Decision relevance

These call sites replace assumptions with inspectable workload structure, but they do not identify a measured ordinary-method bottleneck. The RF and PRB semantics in [SEMANTICS.md](SEMANTICS.md) prevent using their raw timings as a same-problem comparison for C. The next decision must respect that mismatch; neither repeated scans nor fixed iteration limits justify implementing a specialized method now.
