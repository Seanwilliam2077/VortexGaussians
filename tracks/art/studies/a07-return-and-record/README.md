# A07《一次重新开始》

[观看影片](run-01/study.mp4) · [末镜头](run-01/check-together.png) · [剪辑意图](INTENT.md) · [固定计划](edit-plan.json)

这是“可燃的数字记忆”的 **agent 剪辑形式草稿**，全部画面来自 A06 合成示例。它把恢复后的浅色场景与同次重置前的真实操作摘要并置，尝试让“重新开始”和“记录仍在”成为同一画面里的两个可辨事实。没有新增模拟、浏览器操作、笔记、素材或调色；不代表作者体验、个人记忆或艺术效果已获验证。

影片为无音频 H.264，1280×960、25 fps、623 帧、**24.920 秒，437,321 字节**。一次主编码，无排版修复。SHA256：`dd218e6b994b94126f348be74a2f3564ae562ebf0f2980deb0037cb66f4541db`。

| 镜头 | 来源与处理 | 计划长度 |
|---|---|---:|
| 原状 | A06 `02-loaded.png`，裁切 40,20,850,530，等比放大 1.2 倍，静帧 | 3 秒 |
| 燃烧 | A06 影片 5.10–18.10 秒，裁切 40,0,850,530，同倍率，保留原片速度 | 13 秒 |
| 重新开始 | A06 `06-reset-scene.png`，同后续裁切与倍率，静帧 | 3.5 秒 |
| 恢复与摘要同屏 | 恢复场景裁切以原尺寸放置；A06 `07-reset-receipt.png` 的 60,400,800,120 区域放大 1.5 倍，静帧并置 | 5.5 秒 |

前后裁切的 20 像素纵向差修正原页面滚动，使同一场景对齐；末镜头则有意改变布局。计划合计约 25 秒，实际容器 24.920 秒，不为整齐时长重编码。原片是带时间戳的屏幕采样，保留其速度不等于恢复未采到的运动或证明实时性能。末镜头的 **0.00 s 是恢复后的场景读数；10.00 s / 3,320 / 1,400 是此前操作摘要**。数字直接来自回执截图，未重写。并置是本片的编辑选择，不是原 UI 同时显示的截图，也不是可恢复仿真的 checkpoint。

主编码返回 0，但之后 `ffprobe -of json` 保存的 stdout 缺失最外层闭合括号，导致 JSON 解析失败。原 [result.json](run-01/result.json)、原 probe 输出与日志完整保留为 `failed`。代码没有对 stdout 做切片；现有记录不足以定位缺字符原因，原因记为 **unknown**。没有重编码。另用 [inspect.py](inspect.py) 读取 flat 元数据并从现成影片解码四张关键帧，结果为 [inspection.json](run-01/inspection.json)；[补充记录](run-01/inspection-addendum.json) 保存命令、源首尾 SHA 和原始异常说明，不掩盖先前失败。父代理还做了[一次全片解码到 null](../../../validation/a07-delivery-review.md)，623 帧、无解码错误；该检查也没有编码。

**Agent 自评：** 四张实际解码图中文字无裁断，末镜头的摘要数字可读；恢复场景与旧摘要不用依赖观众记住前一镜头。燃烧段仍只有局部深色变化，且部分被火焰遮挡，不能看作整个材料烧毁。结尾仍带明显的操作记录语言；它是否构成有说服力的作品观看顺序，仍待作者判断，不把并置直接解释为不可逆留痕或特定情绪。

复现入口为 `python edit.py`（仅核输入和打印计划）；`python edit.py --execute --out 新目录` 才会编码。本次预算已用完并停写，不再执行。A06 完整记录保持原样。
