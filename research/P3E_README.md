# P3e: local first-order field approximation

This is one fixed, exploratory diagnostic on the previously observed stationary condition with physics seed 11 and render seed 101. It compares DD against a deployable local affine approximation. It does not add parameter tiers after seeing errors, and it is not a new heldout evaluation. The specification is in [P3E_PROTOCOL.md](P3E_PROTOCOL.md).

Both trajectories run for 180 steps at dt=1/60, with the same 600-slot physical simulation, 9,600-slot tracer renderer, source rate, optical weights, and renderer. The affine method rebuilds its groups from its own current tracer positions every step. These groups are temporary local approximation domains, not persistent material particles.

There are `min(600,ceil(N/16))` groups. Recursive partitioning sorts along the longest axis (ties x, then y, then z), breaking coordinate ties by stable birth ID. With a requested K leaves, the left branch receives `floor(K/2)` leaves and `floor(N*leftK/K)` members. Leaf IDs follow depth-first order; centroids sum members in stable-ID order. Each group makes exactly seven raw queries at its centroid and its six axis offsets with delta=eps/8. Central finite differences form the induced-velocity Jacobian and Tb gradient. The reconstructed Tb is clipped to [0,1.6]. External forces and the velocity clamp apply at the actual tracer position, once after reconstruction. No thermal-support weight is invented for an affine prediction.

The DD run additionally captures all actual input positions after births and before advection at frames 15,30,…,180. A read-only diagnostic builds the same local models on those DD inputs and evaluates extra direct reference queries. The 12 complete diagnostics contain 56,160 point observations, 3,510 models, and 24,570 model-stencil queries. They explain field errors at common positions; they are not a third deployable trajectory, a cumulative error bound, or a separate STOP threshold.

Run from the repository root:

```text
node --test research/tests/*.test.mjs
node research/p3e-smoke.mjs --out research/runs/p3e-smoke-final
node research/p3e-run.mjs --suite quick --out research/runs/p3e-quick --baseline research/runs/p3d-full
node research/p3e-run.mjs --suite all --out research/runs/p3e-full --baseline research/runs/p3d-full --baseline-archive PATH_TO_IMMUTABLE_P3D_ZIP
```

Use the existing research Playwright dependency, or `PLAYWRIGHT_MODULE`. Set `BROWSER_EXECUTABLE` or `--browser-executable` if selecting an installed browser. No host-specific paths are embedded. `quick` is two 15-step wiring checks and never performs timing. The only other suite is `all`; there is no timing-only bypass. Output manifests are never overwritten.

Both quality trajectories are completed before deciding whether to time them. Each saves 181 lightweight physical/birth trace rows, a separate 181-entry tracer hash trace, 13 Float64 particle checkpoints, and six linear RGBA32F images with PNG previews. Full quality output has 26 particle files, 12 RGBA files, 12 previews, 12 byte-mask files, and 12 independent diagnostic JSON files. Binary and diagnostic records include SHA256. Quantitative image metrics use raw linear buffers, not previews.

`manifest.quality` contains `comparisons[0]`, `masks`, `diagnostics`, `legacyRegression`, `gate`, `failures`, and `complete`. Raw case JSON retains `trace`, `tracerTrace`, `snapshots`, `checkpoints`, `captures`, and diagnostic file references. Each diagnostic file stores the original captured inputs plus all models, seven stencil positions and raw values, membership IDs, radii, velocity Jacobians, Tb gradients, direct fields, predictions, and final/pre-clamp velocities. Each prediction maps back to its actual input by stable ID. Summaries retain additive squared errors and signed Tb sums, both raw and clipped, with stencil and direct support populations separated.

The deployable affine trajectory must meet the existing DD-relative path and image gates: all sampled matched-ID position RMSE at most .007 and p99 at most .035; pooled foreground RGB and alpha NRMSE at most 5%; no unmatched IDs, source-capacity limitation, or unexpected fallback. Missing or retired candidate IDs retain explicit ID lists and optical weights. Zero matched populations produce null path metrics. Finite empty/dark candidate images are valid data with image error. These are scientific quality failures, not software errors. Nonfinite states, incomplete raw evidence, corrupted provenance, and physical/birth sequence drift fail execution validity.

If quality fails, `status` can still be `passed`, `stageStatus` is `stopped_after_quality`, `protocolComplete` is true for a completed `all` run, and `timingSkipped` gives the predeclared reason. The ten planned timing cases remain listed but are not run. No extra budget, adjusted threshold, or rescue configuration is introduced. `decision.engineeringGo` is false. Same-position diagnostic errors cannot override this gate.

If quality passes, ten independent timing runs follow: DD/affine, affine/DD, DD/affine, affine/DD, DD/affine. This is a 3:2 partially balanced order. Each run warms 20 frames, resets, and records 41 samples over frames 60–180 every third step. `gl.finish` drains prior work and completes each measured frame. The result is synchronized wall-clock latency, not pure GPU time or a steady-state claim. Grouping, model construction, reconstruction, advection, sorting/upload, draw submission, and completion all count. Substages are included in `tracerMs`, not additional costs to add again.

No diagnostic or dense tracer-hash collection runs inside the timing loop. Timing initial/final tracer hashes, full statistics, counters, and field metadata are compared outside timing against the same-method quality run; all 181 lightweight traces must also match. Five run medians define the central value; the median of five run p95 values defines the tail, not pooled-frame p95. A positive engineering decision requires complete evidence, the quality gate, at least 1.5× central speedup over DD, and a tail no worse than DD. It would establish only a result for this one condition.

The old DD reference is authenticated through `lib/p3e-baseline.json`, which pins the manifest and stationary DD raw JSON taken directly from the P3d archive with SHA256 `1c486850a886e5291d7b1aa6e1ce125b3988d694064c4c38f75920fffd72bc44`. Those JSON hashes are checked before and after each run. An optional archive argument must match the fixed SHA. Portable reproduction can use the two authenticated JSON files without copying the entire prior archive; binary hashes are then taken from these authenticated records, while any old binaries present are rehashed. All newly produced binaries are always verified. DD must reproduce the prior 181 tracer/lightweight traces, old snapshot fields, 13 particle hashes, and six raw-image hashes. Source fingerprints are checked at the beginning and end.
